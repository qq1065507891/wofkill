# 狼人杀智能体框架 V1 - 补充与实战改进建议

这份文档指出了 V1 设计文档在真实对局落地时可能遇到的实战边界问题，并提出了一套以**认知协处理器（Cognitive Coprocessor）**为核心的架构升级方案，以彻底解决大模型的上下文爆炸与逻辑迷失问题。

## 一、规则引擎缺失的真实场景

设计里的规则引擎太“教科书”，缺了大量实战中必须处理的边界。

### 1.1 警徽系统严重不足
设计只提了一个节点 `sheriff_election`，但真实狼人杀的警徽系统极其复杂：
* **竞选流程**：上警 → 发言 → 退选 → 投票，不是一步到位的。
* **警徽流**：预言家拿到警徽后会公布“我今晚会验 X 号，如果我死了，警徽飞给 Y 号”。这是预言家最重要的信息传递手段，设计里完全没提。
* **撕徽/传徽**：警长死亡时可以选择撕掉（0.5票变回1票）或传给某人，这是关键战略决策。
* **毒杀限制**：警长被毒死能不能传徽？不同板子规则不同，必须配置化。
* **建议**：警徽系统单独建模，不能塞在 `sheriff_election` 一个节点里。

### 1.2 死亡时机与技能触发冲突
设计中 `night_hunter_idiot_status` 和 `post_exile_skills` 分开了，但没处理：
* 猎人被女巫毒死能不能开枪：这是最常见的规则争议，必须明确配置。
* 同夜双死：狼人刀了 A，女巫毒了 B，两人同时死亡。如果 B 是猎人，开枪打谁？此时 A 的遗言还没发表。
* 白痴被毒死能不能翻牌：白痴的技能只在被放逐时触发，被毒死不触发。
* **建议**：`deaths` 不只是 `List[DeadPlayer]`，需要记录死亡原因（`wolf_kill` / `witch_poison` / `exile` / `hunter_shot`）和死亡时机（`night` / `day_vote`），技能触发条件按 `(死亡原因, 死亡时机)` 组合判断。

### 1.3 缺失的常见规则
* 平安夜/平安日：没有人死亡的夜晚/白天，流程怎么走。
* 自爆：很多板子允许狼人白天自爆直接跳过发言进入黑夜。
* 平票处理：投票平票怎么办？加票？PK？直接平安日？
* 遗言权：首夜死者有没有遗言？白天被放逐的有没有遗言？不同规则差异很大。
* 女巫首夜自救：能不能自救？只在首夜能自救还是永远不能？这个配置必须有。

## 二、游戏流程的实战缺陷

### 2.1 发言顺序的影响
设计里 `day_speech` 按发言顺序生成，但没说发言顺序怎么定。真实狼人杀中：
* 有警长时：警长决定发言顺序（通常是“从死左/死右开始”）。
* 没警长时：随机或固定规则。
* 发言顺序本身就是博弈：后发言的人听到前面所有人的发言后可以调整策略。先发言的人没有这个优势。

### 2.2 多轮发言与对话
设计把白天发言当成每人说一次就完了。真实狼人杀白天的流程通常是：
1. 警长竞选发言（上警的人发言）
2. 投票选警长
3. 自由讨论/多人多轮发言
4. 警长归票
5. 投票放逐
* **建议**：白天阶段至少拆成 `free_discussion`（多轮）+ `summarize_positions` + `sheriff_endorse`（警长归票）+ `vote`。

### 2.3 夜间沟通
真实狼人杀中狼人之间会“刀法讨论”，可能存在分歧（有人想刀预言家，有人想刀女巫）。
* **建议**：`night_wolves` 拆成 `wolf_discussion`（狼人内部多轮讨论）+ `wolf_consensus`（达成共识或投票决定）。

## 三、RAG 冷启动方案与 Agent 输出控制

### 3.1 RAG 冷启动
* **Phase A — 规则驱动种子**：从规则引擎的合法动作集合和结算结果自动生成“如果 X 发生了，常见应对是 Y”的基础策略文档。
* **Phase B — 对局自举**：先跑 50 局纯 LLM 对局（不接 RAG），筛选“决策导致胜利/失败”的片段作为种子案例。
* **Phase C — 人工精选**：人工挑选高质量片段，标注正反面教材。

### 3.2 结构化输出的强制约束
不要指望 LLM 乖乖输出 JSON。建议用 `structured output` / `function calling` 模式，把合法选项直接编码到 schema 的 enum 里，从根源杜绝非法目标。

### 3.3 多步生成策略
一步生成完整的 JSON 对弱模型太难，建议拆步：
1. 先生成 `internal_scratchpad`（内心戏，纯文本）。
2. 再生成 `action` 和 `target`（结构化，用 function calling）。
3. 最后生成 `speech`（自然语言）。

## 四、核心架构升级：认知协处理器 (Cognitive Coprocessor)

为了彻底解决“不同角色信息需求差异大”、“LLM 无法装不知道导致泄露私有信息”、“记忆系统不会自动更新”以及“多轮对话上下文爆炸”的核心痛点，**必须将 LLM 从“全能大脑”降级为“推理与生成引擎”，并在其前端引入“认知协处理器”管线。**

传统做法是将历史发言直接拼接成 Prompt 塞给大模型，这必然导致成本失控与逻辑幻觉。认知协处理器通过以下 8 个阶段进行拦截与提炼：

### 4.1 认知管线工作流

1. **Structured World State (结构化世界状态)**
   * **职责**：剥离冗长的自然语言。不再记录“1号玩家说他怀疑3号”，而是存储到底层图数据库或关系表中：`{"source": "P1", "target": "P3", "action": "suspect", "reason": "vote_pattern", "day": 2}`。
   * **收益**：将剧本逐字稿转化为极度压缩的客观事实网络。

2. **Attention Filter (注意力过滤器)**
   * **职责**：消除与当前 Agent 视角无关的信息噪音，实现绝对的“信息隔离”。
   * **运行机制**：按角色需求裁剪数据。例如，女巫视角只保留“刀口”、“银水行为”和“求药发言”；平民视角过滤掉一切夜间行动逻辑，只保留“票型”和“对跳链”。

3. **Salience Engine (显著性引擎)**
   * **职责**：防止 LLM 在长文本中抓不住重点，为过滤后的事实打上权重。
   * **运行机制**：
       * **高权重**（直入 Prompt）：我发过金水的人今天反水投了我。
       * **中权重**（摘要入 Prompt）：5号和6号在第一天的轻微互踩。
       * **低权重**（仅留存长期记忆）：已出局明牌玩家的常规水文发言。

4. **Belief Updater (信念更新器)**
   * **职责**：剥离大模型的数学与概率计算，负责“认知矩阵”的自动演进。
   * **运行机制**：跑在传统的代码逻辑或轻量级贝叶斯网络上。当发生“某人跳预言家”或“死亡揭晓”时，自动计算并更新脑内的 `role_probabilities`（如：狼人初始矩阵中，队友的身份直接确认为 100%）。大模型不盘概率，只接收概率结果。

5. **Contradiction Engine (矛盾发现机)**
   * **职责**：增强逻辑敏锐度，代替大模型去寻找关系图谱中的逻辑漏洞。
   * **运行机制**：后台交叉比对（例如：“8号跳预言家，但首日未投其查杀目标”）。引擎将此转化为一条**高优警报 (Alert)**，直接喂给大模型作为发言的攻击抓手。

6. **Strategy Selector (策略选择器)**
   * **职责**：对接 Persona Router，控制宏观行为边界。
   * **运行机制**：基于前置得出的“信念”和阵营任务，选择策略包。如：判定自身面临出局风险（Belief）+ 自身是狼（Role），则激活 `aggressive_defense`（悍跳反击）策略。

7. **Local Context Builder (局部上下文构建器)**
   * **职责**：组装最终的极简 Prompt。
   * **产出示例**：最终发给 LLM 的不再是洋洋洒洒的数千字，而是高度压缩的结构体：
     * *你是谁*：狼人，采取“倒钩”策略。
     * *你的信念*：你认为3号是真预言家（置信度90%）。
     * *显著事件*：4号刚刚踩了3号。
     * *行动指令*：请利用“4号前保后踩的逻辑矛盾”攻击他，从而暗保3号。

8. **LLM (大语言模型)**
   * **最终形态**：此时的大模型完全脱离了记账、算概率、梳理逻辑的苦力活，只需发挥其最擅长的事：**基于高度压缩的结构化前提，生成带有强烈角色人格、极具煽动性的自然语言发言。** 彻底解决降智与泄密风险。
