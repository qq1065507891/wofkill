# Live Context Ablation Harness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a local, deterministic live-context ablation harness that applies module toggles to `AgentContext` before injected agent execution and compares paired baseline vs ablated decisions without calling real LLMs, networks, or databases.

**Architecture:** Extend the existing `werewolf_agent.evaluation.ablation` module with context-level toggle dataclasses, a pure `apply_ablation_toggles()` helper, and a `LiveContextAblationHarness` that accepts already-built `AgentContext` objects plus an injected runner function. The harness computes decision deltas only; it does not call `PlayerAgent.act()` directly and does not claim win-rate or full-game causal metrics.

**Tech Stack:** Python dataclasses, existing Pydantic `AgentContext` / `PlayerAction` schemas, pytest, injected fake runner for tests.

---

## Scope

This plan implements the delayed Phase 7B from
`docs/superpowers/specs/2026-06-16-evaluation-feedback-loop-design.md` in a
minimal, testable form.

In scope:

- Toggle RAG, reflection memory, possible worlds, simulator predictions, skill
  advice, and persona snapshot at the `AgentContext` field level.
- Return modified context copies via `AgentContext.model_copy(deep=True, ...)`.
- Run paired baseline vs ablated decisions through an injected callable. This is
  called `live_context` mode because it tests the live prompt/context boundary,
  not a full live game.
- Produce decision-level deltas: action changed, target changed, confidence
  delta, failed pair count, and unsupported causal win-rate metrics.
- Keep this harness independent of live game execution and model providers.

Out of scope:

- Running full same-seed games.
- Calling `PlayerAgent.act()` directly inside the harness. Callers may pass
  `PlayerAgent.act` as the injected runner later, but tests must use fake
  runners and the harness must not import model providers.
- Importing or invoking model routers.
- Writing RAG, memory, evaluation, or LangSmith stores.
- Claiming win-rate, game outcome, or long-horizon causal impact.

## Toggle Semantics

`AblationToggleSet(removed_modules=[...])` normalizes module names by stripping
blank entries and removing duplicates while preserving order.

The toggle mapping is:

- `rag`: clear `context.rag_hints`.
- `reflection`: clear `context.reflection_memory_hints` and
  `context.error_pattern_hint`.
- `possible_worlds`: clear `context.possible_worlds`.
- `simulator`: clear `context.simulation_predictions`.
- `skills`: clear `context.skill_analyses`, `context.skill_analysis_hints`,
  and remove `skill_tactical_advice` from `context.strategy_directive`.
- `persona`: clear `context.persona_snapshot`.

The helper must not mutate:

- the original `AgentContext`;
- nested `strategy_directive`;
- any nested lists or dicts reused by the caller in the returned context. Use
  `context.model_copy(deep=True, update=...)` or an equivalent deep-copy
  strategy.

Unknown module names should be preserved in `removed_modules` and recorded in
the report's `unsupported_metrics` as `unsupported_toggle:<module>`, but should
not fail the run. This lets experiments surface typos without breaking batch
evaluation.

## Pair And Failure Semantics

`LiveAblationPair.context_id` is generated by the harness. It should be stable
within a run and derived from the context plus index:

```text
{index}:{agent_id}:{task_type}:{phase}:D{day_number}:N{night_number}
```

Runner output conversion rules:

- `PlayerAction`: use `action_type.value`, `target_id`, `confidence`.
- `FallbackAction`: use `action_type.value`, `target_id`, and confidence `0.0`
  because the schema has no confidence field.
- `DecisionSnapshot`: use `action_type`, `target_id`, `confidence`.
- `dict`: read `action_type`, `target_id`, `confidence`; default confidence
  to `0.0`.
- other test doubles: use attributes with the same names; default confidence to
  `0.0`.

Failure rules:

- If baseline or ablated runner call raises, the pair still counts toward
  `pair_count`.
- The failed side becomes `LiveAblationDecision(action_type="", target_id=None,
  confidence=0.0, raw={}, error=<message>)`.
- `failed_pair_count` increments when either side has `error`.
- `action_changed_count`, `target_changed_count`, and `avg_confidence_delta`
  exclude failed pairs from their denominators/calculations.
- If all pairs fail, `avg_confidence_delta` is `0.0`.

```python
def test_live_context_ablation_harness_reports_paired_decision_deltas():
    import pytest

    from werewolf_agent.evaluation.ablation import (
        AblationToggleSet,
        LiveContextAblationHarness,
    )

    calls = []

    def runner(context):
        calls.append(context)
        if context.rag_hints:
            return _decision("vote", "p02", 0.8)
        return _decision("vote", "p03", 0.5)

    report = LiveContextAblationHarness(runner=runner).run(
        [_context()],
        toggles=AblationToggleSet(["rag"]),
    )

    assert report.mode == "live_context"
    assert report.removed_modules == ["rag"]
    assert report.pair_count == 1
    assert report.failed_pair_count == 0
    assert report.action_changed_count == 0
    assert report.target_changed_count == 1
    assert report.avg_confidence_delta == pytest.approx(-0.3)
    assert report.pairs[0].baseline.target_id == "p02"
    assert report.pairs[0].ablated.target_id == "p03"
    assert calls[0].rag_hints
    assert calls[1].rag_hints == []
```
