# README 更新设计

## 目标

基于当前 `master` 的实际代码和配置更新项目根目录 `README.md`，使新开发者能够完成环境安装、测试、API 启动和真实对局运行，并能正确理解项目的安全边界、输出产物与当前实现状态。

## 更新策略

采用增量重写：保留仍然准确的项目定位、目录结构、Docker、持久化和开发约束，合并重复内容并修正过时描述。README 保持中文 UTF-8，不扩展为完整架构手册。

## 内容结构

1. 项目定位和核心边界。
2. 当前功能与目录结构。
3. Conda、dotenv 和 Docker 快速开始。
4. API Dashboard、真实对局与审计报告命令。
5. 模型路由、存储和输出路径。
6. 测试命令及 Windows 本地 `--basetemp` 建议。
7. 当前关键契约：票权显示、discussion summary、speech repair、Reflection 和截断指标支持状态。
8. 开发约束与详细文档入口。

## 真实性约束

- 命令、路径和环境变量必须能在当前仓库中找到对应实现。
- 不写入或示例化真实凭据，只引用 `.env.example` 中的变量名。
- 区分自动化测试通过与真实生产对局验收；不把超时实局描述为成功。
- 规则真值仍由 `RuleEngine` 和规则集配置决定，LLM、RAG 与记忆不能覆盖裁判结果。
- 公开视图、玩家私有视图和主持人视图的边界应与当前 API 契约一致。

## 验证

- 检查 README 中引用的本地路径均存在。
- 对命令入口运行 `--help` 或等价的只读导入检查。
- 搜索 README 中的旧模型、旧任务管线和错误票权描述。
- 运行 Markdown 基础检查，并执行 `git diff --check`。
